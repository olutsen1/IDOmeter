# IDometer 2 — программа и прошивка, версия 0.4

Приём данных с устройства (или симулятора), живые графики, метки интервенций
по клавишам, запись сессии и анализ откликов на метки. Всё работает на одном
компьютере с Windows: без малинки, MQTT-брокера и Grafana.

## Установка (один раз)

1. Установите Python 3.11 или новее с python.org. В установщике отметьте
   **«Add python.exe to PATH»**.
2. Распакуйте эту папку куда удобно и запустите `1_install.bat`.

## Попробовать без железа

Запустите `2_demo_with_simulator.bat`. Откроются два окна: консоль симулятора
и приёмник. При первом запуске Windows может спросить про доступ к сети для
Python — разрешите для частных сетей.

Нажмите **R** (запись), затем ставьте метки клавишами **1…9**, **Пробел**, **B**.
Симулятор с вероятностью 80 % «отвечает телом»: через 1–2,5 с подъём кожной
проводимости, замедление и затем ускорение пульса, иногда глубокий вдох.
Ещё он сам выдаёт спонтанные ответы, не связанные с метками, как настоящее тело.

Через несколько минут снова **R** и анализ:

```
python analyze.py sessions\ИМЯ_ПАПКИ --truth sim_truth.csv
```

Анализ напечатает, нашёл ли он заложенные ответы и насколько точно сведены часы,
а в `sessions\ИМЯ_ПАПКИ\analysis` положит графики и таблицу.

## Работа с прибором

Как залить новую прошивку — в `..\firmware\HOW_TO_FLASH_ru.txt`. После этого
запускайте `3_receiver_real_device.bat`.

## Клавиши приёмника

| Клавиша | Действие |
|---|---|
| 1…9, Пробел, B | метка соответствующего типа (типы — в `config.json`) |
| N | заметка: время фиксируется в момент нажатия N, затем пишете текст, Enter |
| Esc | отменить заметку |
| R | старт / стоп записи |
| F | заморозить прокрутку (тогда графики можно листать мышью) |

Метки, поставленные до нажатия R, видны на графиках, но в файл не попадают.

## Файлы

| Файл | Назначение |
|---|---|
| `protocol.py` | формат пакета; его же будет реализовывать прошивка |
| `clocksync.py` | сведение часов устройства и компьютера |
| `simulator.py` | симулятор устройства (`python simulator.py --help`) |
| `receiver.py`, `receiver_core.py` | приёмник с окном |
| `analyze.py` | анализ записанной сессии |
| `config.json` | названия меток, порт, калибровка EDA |
| `..\firmware\IDometer_fw` | прошивка прибора для Arduino IDE |

Сессия — это папка с `fast.csv` (PPG 100 Гц), `slow.csv` (EDA и дыхание 20 Гц),
`markers.csv`, `packets.csv` (служебное, для точного пересчёта времени)
и `meta.json`. Всё читается Excel или Python.

## Как устроено время

Устройство не знает реального времени. Каждый пакет несёт номер и показание
собственного счётчика микросекунд. Приёмник отмечает момент прихода пакета
и по **нижней огибающей** задержек строит прямую «время устройства → время
компьютера», учитывая дрейф кварца. Метки ставятся по часам компьютера, поэтому
сигналы и метки оказываются на одной шкале. При анализе часы сводятся заново
по всей сессии.

## Протокол v1 (для прошивки)

UDP на порт 5005 приёмника, little-endian. Заголовок 20 байт:
`'ID'`, version=1, type=1, `uint32 seq`, `uint64 t0_us`, `uint16 n_ticks`,
`uint16 flags`. Затем `n_ticks × uint32` ИК, `n_ticks × uint32` красный,
`n_ticks/5 × int32` EDA, `n_ticks/5 × int32` дыхание. Базовая частота 100 Гц,
медленные каналы 20 Гц, по умолчанию 10 тактов (100 мс) на пакет.
Подробно — в начале `protocol.py`.

## Калибровка EDA

В `config.json`, раздел `eda_calibration`:

- `{"type": "linear", "gain": 0.001, "offset": 0}` — для симулятора (он шлёт наносименсы);
- `{"type": "table", "points": [[сырое, мкСм], ...]}` — для Grove GSR после
  калибровки на резисторах;
- `{"type": "none"}` — показывать сырые отсчёты АЦП.
